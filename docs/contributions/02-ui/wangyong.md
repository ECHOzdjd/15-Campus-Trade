### 组件库规范整理

#### Button 组件
- **Primary**：主要操作，填充主色
- **Secondary**：次要操作，填充次色或边框
- **Ghost**：最小化操作，仅文字
- **Outline**：边框样式
- **Disabled**：禁用状态
- **Loading**：加载中状态

#### Input 组件
- **默认态**：浅灰背景（#f3f3f5）
- **焦点态**：蓝紫边框，阴影
- **禁用态**：灰色文字、禁止光标
- **错误态**：红边框，错误提示
- **成功态**：绿边框或绿勾

#### Badge（标签）组件
- 用于表示状态、分类或标签
- 四种变体：default、primary、secondary、destructive
- 支持小、中、大三种尺寸

## 主要设计原则

### 1. 一致性原则
所有设计元素、颜色、字体、间距都遵循统一的规范，确保产品整体风格的统一。

### 2. 可读性优先
- 合理的字体大小
- 充足的行高和字间距
- 高对比度的色彩搭配
- 清晰的视觉层级

### 3. 可访问性
- WCAG AA 标准的色彩对比度
- 支持键盘导航
- 清晰的焦点指示器
- 适当的 alt 文本

### 4. 效率设计
- 减少用户的操作步骤
- 提供清晰的反馈
- 合理的默认值
- 快速恢复机制

## 遇到的问题和解决

### 问题 1：深色模式颜色选择困难
**背景**：需要在保持品牌色的同时，确保深色模式的可读性
**解决方案**：
- 采用 OKLCH 色彩空间，提供更直观的亮度控制
- 为浅色和深色主题分别设计颜色系统
- 在 theme.css 中使用 CSS 变量实现主题切换
- 测试所有色彩组合的对比度

**学到的**：色彩空间的选择很重要，OKLCH 比 RGB/HSL 更适合主题设计

### 问题 2：表单验证反馈设计
**背景**：需要在不干扰用户的情况下，清晰地显示验证错误
**解决方案**：
- 实时验证提示（当用户停止输入 500ms 后）
- 颜色+图标组合表示状态
- 清晰的错误信息提示
- 成功状态也给予反馈

**学到的**：用户体验不只是漂亮，更要实用

### 问题 3：登录/注册的一致性
**背景**：两个页面需要保持风格一致，但功能结构不同
**解决方案**：
- 复用相同的卡片容器、输入框等组件
- 相同的色彩和排版规范
- 统一的加载状态和错误提示
- 清晰的步骤提示（注册页）

**学到的**：组件化思想在视觉设计中也很重要

### 问题 4：icon 库选择
**背景**：需要找到合适的 icon 库，与设计风格匹配
**解决方案**：
- 选择 Lucide React icon 库（线性风格，简洁）
- 统一的 icon 尺寸（16px/20px/24px）
- 与设计系统颜色集成
- 减少自定义 icon，使用库中的标准 icon

**学到的**：好的 icon 库选择能大幅提高设计和开发效率

## 心得体会

通过这个校园二手交易平台的设计项目，我获得了以下宝贵经验：

1. **系统化设计的重要性**：建立完整的设计系统（色彩、排版、组件）能大幅提高产品的一致性和开发效率。

2. **数据驱动的设计**：使用规范和令牌而不是硬编码值，让设计更容易维护和扩展。

3. **深色模式的复杂性**：不仅仅是色彩反转，需要深入思考每个颜色的用途和可读性。

4. **跨端适配**：同一个设计系统需要在不同的端口上工作，需要充分考虑各种场景。

5. **文档的价值**：详细的设计文档和规范能帮助开发团队更准确地理解设计意图，减少沟通成本。

6. **用户视角很重要**：最终的设计要为用户服务，需要思考用户的心智模型和使用场景。
