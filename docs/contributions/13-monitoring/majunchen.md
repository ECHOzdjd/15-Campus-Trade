## 遇到的问题和解决

1. 问题：监控接口如果只写代码，不写字段说明，后续很难知道每个指标的含义。  
   解决：在 `docs/monitoring.md` 中用表格列出字段、含义和示例响应。

2. 问题：健康检查既要满足 Docker 检查，也要保持原来的 `/api/health` 可访问。  
   解决：两个路径复用同一个处理函数，并在文档中同时说明。

3. 问题：错误率统计需要明确口径。  
   解决：将状态码大于等于 400 的请求计入错误请求，并在文档中写清楚。

## 心得体会

监控文档不能只写“已经实现”，还要说明怎么查、查到什么、字段代表什么。这样后面无论是继续做前端管理页，还是做 Docker 部署检查，都可以直接复用这些接口和说明。
